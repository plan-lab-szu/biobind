## Bosphorus evidence

The historical combined metric adds detection failures to matching misses.
A detection failure produces no template and therefore does not by itself
show that a system returned a unique verdict or issued another credential.
Run `R-BOSPHORUS-REANALYSIS-20261114` separates these stages using the same
archived scores and fixed thresholds. Its public output contains aggregate
counts and intervals, input hashes, the script hash and bootstrap settings.
The original source JSON files remain unchanged.

For the original candidate attended-capture grouping, 26 of 3,273 probes
fail detection. At the LFW per-pair FMR target of 10^-4, 32 of the 3,247
detected probes miss the gallery, giving 0.99% with a 95% subject-cluster
interval of 0.57–1.47%. At 10^-5, 125/3,247 gives 3.85% (2.85–4.93%).
The group name records the original experimental grouping; no operational
quality or acceptance gate was run. The bootstrap resamples whole subjects
while holding the gallery and thresholds fixed. These descriptive rates
are not adaptive attack bounds or measurements of duplicate issuance.

See [the biometric README](../experiments/biometric/README.md) for commands
that reproduce separated counts without licensed records, reproduce the
cluster intervals with locally obtained records, or render the revised
black-text table. The old generator still reproduces the arXiv-v1 tables.
Images, embeddings, per-probe scores and failed-image identifiers are not
added to this release.

## Interpretation of the implementation

The four enrollment conditions apply to the stated append-only composition
model. The conditional security arguments retain their cryptographic,
trusted-capture and external attempt-budget assumptions. Human supervision
is a deployment choice; unattended enrollment would need controls meeting
the same assumptions. A per-device counter alone does not enforce an
aggregate budget across devices or stations.

The prototype committee is simulated. Real BGV component and full-capacity
history tests remain separate from that pipeline; finite checkpoints are
not a general cryptographic correctness proof. The trusted-hardware,
presentation-attack and independent proof-review limitations remain.
